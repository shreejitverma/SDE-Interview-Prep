# Comparison: Locks and Barriers

Locks and barriers are fundamental synchronization primitives with distinct coordination goals.
Locks provide mutual exclusion to protect short critical sections, ensuring that only one thread can execute the protected code at a time.
Barriers are used in parallel applications that proceed in distinct phases, ensuring that no thread can start the next phase until all threads have completed the current phase.
The performance of both primitives depends heavily on minimizing network contention, managing space complexity, and leveraging the underlying hardware architecture.

## Hardware Primitives

Atomic read-modify-write instructions are hardware-supported operations that read a memory location, modify its value, and write it back in a single indivisible step.
A test-and-set instruction returns the current value and unconditionally sets it to a non-zero value.
A fetch-and-increment instruction returns the current value and increments it by a specified amount.
A fetch-and-store swap instruction atomically exchanges a register value with the value in memory.

## Scalability Metrics

The scalability of a synchronization algorithm is evaluated across three primary dimensions.
Latency measures the direct overhead of acquiring or releasing a primitive when it is uncontended.
Waiting time measures the delay experienced by a thread before it can acquire a contended primitive.
Contention measures the amount of network traffic or bus transactions generated by multiple processors competing simultaneously.

## Lock Algorithm Comparison

Locks typically encounter scalability issues when multiple threads spin on a single shared variable.
This centralized spinning creates a hot spot and causes cache invalidation storms across the network when the lock is finally released.

| Algorithm | Space Complexity | Fairness | Contended Network Traffic | Hardware Primitives |
| :--- | :--- | :--- | :--- | :--- |
| **Naive Spinlock** | O(1) | None | High (linear per release) | test-and-set |
| **Caching Spinlock** | O(1) | None | Medium (invalidation storm) | test-and-set |
| **Exponential Backoff** | O(1) | None | Medium (reduced by delay) | test-and-set |
| **Ticket Lock** | O(1) | FIFO | Medium (linear reads) | fetch-and-increment |
| **Anderson Lock** | O(P) static | FIFO | Low (constant per handoff) | fetch-and-increment |
| **MCS Lock** | O(N) dynamic | FIFO | Low (constant per handoff) | fetch-and-store (swap) |

### Lock Mechanisms

A naive spinlock repeatedly executes test-and-set on a shared flag, consuming continuous network bandwidth even while waiting.
A caching spinlock spins on a cached read and only attempts test-and-set when the lock appears free, which still causes an invalidation storm upon release.
An exponential backoff lock dynamically increases the delay between consecutive polling attempts to smooth out network traffic bursts.
A ticket lock uses request and release counters to grant lock access in strict FIFO order, though threads still spin on a single shared release counter.
An Anderson lock maintains a padded circular array where each thread spins on a unique locally-cached element, requiring space proportional to the total number of processors.
An MCS lock constructs a linked list of waiting threads where each thread spins on a local flag in its own node, achieving constant network transactions and dynamic space allocation.

## Barrier Algorithm Comparison

Barrier algorithms face scalability issues related to the critical path length and the number of messages required to notify all threads that a phase is complete.

| Algorithm | Network Messages | Critical Path | Space Complexity | Atomic Instructions | Best Used For |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Centralized** | O(N) | O(N) | O(1) | Yes | Small scale SMPs with broadcast cache coherence. |
| **Combining Tree** | O(N) | O(log_K N) | O(N) | Yes | Medium systems where hot spots must be avoided. |
| **MCS Tree** | O(N) | O(log_4 N) | O(N) | Yes | Large-scale NUMA or cache-coherent systems. |
| **Tournament** | O(N) | O(log_2 N) | O(N) | No | Distributed clusters or systems without atomics. |
| **Dissemination** | O(N log_2 N) | O(log_2 N) | O(N log N) | No | Systems lacking shared memory targeting lowest latency. |

### Barrier Mechanisms

A centralized barrier uses a single shared counter and a shared sense-reversing flag to coordinate threads, suffering from hot-spot contention on large systems.
A combining tree barrier distributes synchronization hierarchically by having groups of threads synchronize at leaf nodes up to a root node, mitigating a single hot spot.
An MCS tree barrier employs a 4-ary tree for optimal arrival tracking and a binary tree for wakeups, guaranteeing that every thread spins only on static locally accessible variables.
A tournament barrier pairs threads in a binary tree hierarchy where a static winner advances to the next round, avoiding expensive atomic read-modify-write instructions.
A dissemination barrier uses a cyclic peer-to-peer signaling pattern over logarithmic rounds without a central root bottleneck, perfectly parallelizing the critical path.

## Pitfalls and Architecture Matching

A centralized barrier or ticket lock performs adequately on a small symmetric multiprocessor but fails to scale on a non-uniform memory access machine.
The MCS lock is highly optimal for cache-coherent non-uniform memory access machines because it prevents all remote spinning during contention.
A tournament barrier relies purely on point-to-point message passing, making it ideal for distributed memory architectures that do not support hardware atomics.
Do not assume that caching spinlocks solve contention, because an invalidation storm still generates substantial network traffic upon lock release.
The Anderson lock requires a statically allocated array sized for all processors, wasting memory if the maximum number of contending processors is large but the actual contention is low.
