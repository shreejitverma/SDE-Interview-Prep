\hypertarget{stdexpected}{%
\subsubsection{\texorpdfstring{1.
\texttt{std::expected}}{1. std::expected}}\label{stdexpected}}

\passthrough{\lstinline!std::expected<T, E>!} is the modern way to
return either a valid result (\passthrough{\lstinline!T!}) or an error
(\passthrough{\lstinline!E!}). It is vastly superior to
\passthrough{\lstinline!std::optional!} (which hides the error reason)
and exceptions (which have unpredictable control flow overhead).

\begin{lstlisting}[language={C++}]
#include <expected>

enum class Error { NotFound, PermissionDenied };

std::expected<std::string, Error> read_file(int id) {
    if (id < 0) return std::unexpected(Error::NotFound);
    return "File Content";
}
\end{lstlisting}

\hypertarget{monadic-operations}{%
\subsubsection{2. Monadic Operations}\label{monadic-operations}}

C++23 introduces functional monadic chaining for both
\passthrough{\lstinline!std::optional!} and
\passthrough{\lstinline!std::expected!}, eliminating the ``Pyramid of
Doom'' (nested \passthrough{\lstinline!if!} checks).

\begin{itemize}
\tightlist
\item
  \textbf{\passthrough{\lstinline!and\_then!}}: Called if the object
  contains a value. Must return another optional/expected.
\item
  \textbf{\passthrough{\lstinline!transform!}}: Called if the object
  contains a value. Can return a raw value (auto-wrapped).
\item
  \textbf{\passthrough{\lstinline!or\_else!}}: Called if the object
  contains an error/is empty.
\end{itemize}

\begin{lstlisting}[language={C++}]
std::optional<User> get_user();
std::optional<std::string> get_email(const User&);

auto email = get_user()
    .and_then(get_email)
    .transform([](auto e){ return e + " verified"; })
    .or_else([]{ return std::optional{"Unknown"}; });
\end{lstlisting}
