\section{CLASSES \& OBJECTS}\label{classes-objects}}

\hypertarget{basic-class-structure}{%
\subsection{1.1 Basic Class Structure}\label{basic-class-structure}}

A class is a blueprint for objects. It encapsulates data and behavior.

\begin{lstlisting}[language={C++}]
#include <iostream>
#include <string>

class Person {
public:      // Access modifier: Public
    std::string name;
    int age;
    
    // Member function (Method)
    void introduce() {
        std::cout << "I am " << name << ", age " << age << "\n";
    }
};

int main() {
    Person p;
    p.name = "Alice";
    p.age = 30;
    p.introduce();
    return 0;
}
\end{lstlisting}

\hypertarget{access-modifiers-encapsulation}{%
\subsection{1.2 Access Modifiers \&
Encapsulation}\label{access-modifiers-encapsulation}}

Encapsulation hides internal state to prevent invalid access.

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!public!}: Accessible from anywhere.
\item
  \passthrough{\lstinline!private!}: Accessible only from within the
  class.
\item
  \passthrough{\lstinline!protected!}: Accessible from the class and its
  derived classes.
\end{itemize}

\begin{lstlisting}[language={C++}]
class BankAccount {
private:
    double balance; // Hidden data

public:
    void deposit(double amount) {
        if (amount > 0) balance += amount;
    }
    
    double get_balance() const { // Read-only access
        return balance;
    }
};
\end{lstlisting}

\hypertarget{constructors-destructors}{%
\subsection{1.3 Constructors \&
Destructors}\label{constructors-destructors}}

Constructors initialize objects. Destructors clean up resources.

\begin{lstlisting}[language={C++}]
class Car {
    std::string brand;
    int* buffer;

public:
    // Default Constructor
    Car() : brand("Unknown"), buffer(new int[10]) {
        std::cout << "Default Constructor\n";
    }

    // Parameterized Constructor
    Car(const std::string& b) : brand(b), buffer(new int[10]) {
        std::cout << "Param Constructor\n";
    }

    // Copy Constructor (Deep Copy)
    Car(const Car& other) : brand(other.brand) {
        buffer = new int[10];
        // memcpy or loop to copy buffer content
        std::cout << "Copy Constructor\n";
    }

    // Destructor
    ~Car() {
        delete[] buffer; // Cleanup
        std::cout << "Destructor\n";
    }
};
\end{lstlisting}

\hypertarget{the-rule-of-three-c98}{%
\subsection{1.4 The Rule of Three (C++98)}\label{the-rule-of-three-c98}}

If you explicitly define one of the following, you likely need all three
to manage resources correctly: 1. \textbf{Destructor}: To free resources
(e.g., \passthrough{\lstinline!delete!} memory). 2. \textbf{Copy
Constructor}: To perform deep copies. 3. \textbf{Copy Assignment
Operator}: To handle assignment (\passthrough{\lstinline!a = b!}).

\begin{lstlisting}[language={C++}]
class Buffer {
    int* ptr;
public:
    Buffer() { ptr = new int[10]; }
    ~Buffer() { delete[] ptr; }

    // Copy Constructor
    Buffer(const Buffer& other) {
        ptr = new int[10];
        // copy data...
    }

    // Assignment Operator
    Buffer& operator=(const Buffer& other) {
        if (this != &other) { // Self-assignment check
            delete[] ptr;     // Free old
            ptr = new int[10]; // Allocate new
            // copy data...
        }
        return *this;
    }
};
\end{lstlisting}

\hypertarget{inheritance-polymorphism}{%
\section{INHERITANCE \& POLYMORPHISM}\label{inheritance-polymorphism}}

\hypertarget{inheritance-basics}{%
\subsection{2.1 Inheritance Basics}\label{inheritance-basics}}

Inheritance allows a class to derive features from another.

\begin{lstlisting}[language={C++}]
class Animal {
public:
    void eat() { std::cout << "Eating...\n"; }
};

class Dog : public Animal { // Dog inherits from Animal
public:
    void bark() { std::cout << "Woof!\n"; }
};
\end{lstlisting}

\hypertarget{virtual-functions-polymorphism}{%
\subsection{2.2 Virtual Functions
(Polymorphism)}\label{virtual-functions-polymorphism}}

Polymorphism allows objects to be treated as instances of their base
class, but behave like their actual derived class.

\begin{lstlisting}[language={C++}]
class Shape {
public:
    // Virtual function: Can be overridden
    virtual void draw() { std::cout << "Drawing Shape\n"; }
    
    // Virtual Destructor (Crucial for inheritance)
    virtual ~Shape() {} 
};

class Circle : public Shape {
public:
    void draw() { std::cout << "Drawing Circle\n"; } // Override
};

int main() {
    Shape* s = new Circle();
    s->draw(); // Prints "Drawing Circle" (Dynamic Dispatch)
    delete s;  // Properly calls ~Circle then ~Shape
    return 0;
}
\end{lstlisting}

\hypertarget{pure-virtual-functions-abstract-classes}{%
\subsection{2.3 Pure Virtual Functions (Abstract
Classes)}\label{pure-virtual-functions-abstract-classes}}

A pure virtual function (\passthrough{\lstinline!= 0!}) makes a class
\textbf{Abstract}. It cannot be instantiated and must be subclassed.

\begin{lstlisting}[language={C++}]
class Interface {
public:
    virtual void execute() = 0; // Pure virtual
    virtual ~Interface() {}
};

class Concrete : public Interface {
public:
    void execute() { std::cout << "Executed.\n"; }
};
\end{lstlisting}

\hypertarget{static-members}{%
\subsection{3.1 Static Members}\label{static-members}}

Shared by all instances of the class.

\begin{lstlisting}[language={C++}]
class User {
public:
    static int userCount; // Declaration
    User() { userCount++; }
};

// Definition (Must be outside class)
int User::userCount = 0;
\end{lstlisting}

\hypertarget{friend-classesfunctions}{%
\subsection{3.2 Friend
Classes/Functions}\label{friend-classesfunctions}}

Friends can access private members.

\begin{lstlisting}[language={C++}]
class Box {
    int width;
public:
    Box(int w) : width(w) {}
    friend void printWidth(Box& b);
};

void printWidth(Box& b) {
    // Can access private 'width'
    std::cout << b.width << "\n";
}
\end{lstlisting}

\hypertarget{part-2-generic-programming-templates}{%
\section{PART 2: GENERIC PROGRAMMING
(TEMPLATES)}\label{part-2-generic-programming-templates}}

Templates are the foundation of Generic Programming in C++. They allow
writing code that works with any data type. This is how the STL is
implemented.

\hypertarget{function-templates}{%
\subsection{4.1 Function Templates}\label{function-templates}}

A function template defines a family of functions.

\begin{lstlisting}[language={C++}]
// Template declaration
template <typename T>
T myMax(T a, T b) {
    return (a > b) ? a : b;
}

int main() {
    std::cout << myMax(10, 20) << "\n";       // T is int
    std::cout << myMax(3.14, 2.71) << "\n";   // T is double
    // std::cout << myMax(10, 3.14) << "\n";  // Error: Mismatched types
    return 0;
}
\end{lstlisting}

\hypertarget{class-templates}{%
\subsection{4.2 Class Templates}\label{class-templates}}

Classes can also be templated to hold data of any type.

\begin{lstlisting}[language={C++}]
template <typename T>
class Box {
private:
    T content;
public:
    Box(T val) : content(val) {}
    
    T getContent() const { return content; }
    void setContent(T val) { content = val; }
};

int main() {
    Box<int> intBox(123);
    Box<std::string> strBox("Hello");
    
    std::cout << intBox.getContent() << "\n";
    return 0;
}
\end{lstlisting}

\hypertarget{multiple-template-parameters}{%
\subsection{4.3 Multiple Template
Parameters}\label{multiple-template-parameters}}

Templates can accept multiple types.

\begin{lstlisting}[language={C++}]
template <typename T1, typename T2>
struct Pair {
    T1 first;
    T2 second;
    
    Pair(T1 a, T2 b) : first(a), second(b) {}
};

int main() {
    Pair<std::string, int> p("Alice", 30);
    return 0;
}
\end{lstlisting}

\hypertarget{non-type-template-parameters}{%
\subsection{4.4 Non-Type Template
Parameters}\label{non-type-template-parameters}}

Templates can take values (integers, pointers) as parameters, not just
types.

\begin{lstlisting}[language={C++}]
// N is a compile-time constant
template <typename T, int N>
class Array {
    T data[N];
public:
    int size() const { return N; }
};

int main() {
    Array<int, 5> arr; // Fixed size array of 5 ints
    // Array<int, 10> arr2 = arr; // Error: Different types
    return 0;
}
\end{lstlisting}

\hypertarget{template-specialization}{%
\subsection{4.5 Template Specialization}\label{template-specialization}}

You can define specific implementations for specific types.

\hypertarget{full-specialization}{%
\subsubsection{Full Specialization}\label{full-specialization}}

\begin{lstlisting}[language={C++}]
template <typename T>
class Formatter {
public:
    void format(T val) { std::cout << "General: " << val << "\n"; }
};

// Specialized for bool
template <> 
class Formatter<bool> {
public:
    void format(bool val) { 
        std::cout << "Boolean: " << (val ? "true" : "false") << "\n"; 
    } 
};
\end{lstlisting}

\hypertarget{partial-specialization-class-templates-only}{%
\subsubsection{Partial Specialization (Class Templates
Only)}\label{partial-specialization-class-templates-only}}

\begin{lstlisting}[language={C++}]
template <typename T1, typename T2>
class MyMap { /* ... */ };

// Partial specialization for when both types are the same
template <typename T>
class MyMap<T, T> { /* Optimized implementation */ };
\end{lstlisting}

\hypertarget{the-typename-keyword}{%
\subsection{\texorpdfstring{4.6 The \texttt{typename}
Keyword}{4.6 The typename Keyword}}\label{the-typename-keyword}}

When a type depends on a template parameter (dependent type), you must
use \passthrough{\lstinline!typename!}.

\begin{lstlisting}[language={C++}]
template <typename T>
void func() {
    // T::iterator *iter; // Ambiguous: Is iterator a type or a static member?
    
    typename T::iterator *iter; // Correct: Tells compiler iterator is a type
}
\end{lstlisting}

\hypertarget{templates-vs-macros}{%
\subsection{4.7 Templates vs Macros}\label{templates-vs-macros}}

Templates are type-safe and processed by the compiler. Macros are text
substitution processed by the preprocessor. Always prefer templates.

\textbf{Summary:} - \textbf{Templates} allow code reuse for different
types. - \textbf{Function Templates} deduce types automatically. -
\textbf{Class Templates} require explicit type arguments. -
\textbf{Specialization} allows handling specific types differently.

\hypertarget{namespace-aliases}{%

\begin{lstlisting}[language={C++}]
#include <iostream>
using namespace std;

namespace Very {
    namespace Long {
        namespace Namespace {
            void function() {
                cout << "Long namespace function" << endl;
            }
        }
    }
}

int main() {
    // Use alias to shorten
    namespace VLN = Very::Long::Namespace;
    
    VLN::function();
    
    // or use using
    using namespace Very::Long::Namespace;
    function();
    
    return 0;
}
