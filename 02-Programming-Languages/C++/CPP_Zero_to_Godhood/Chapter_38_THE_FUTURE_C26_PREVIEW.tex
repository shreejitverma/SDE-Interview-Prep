\chapter{C++26 - THE NEXT FRONTIER}
\label{chap:cpp26}

C++26 is the ``Godhood'' standard, finally bringing features that have been in development for over a decade. It transforms C++ from a language of templates and macros into a language of compile-time introspection and guaranteed safety.

\section{Static Reflection (\texttt{std::meta})}

Reflection is the most significant addition to C++ since Move Semantics. It allows the compiler to reason about the structure of the program itself.

\subsection{The Reflection Operator (\texttt{\^})}
The \texttt{\^} operator (called ``hat'') produces a ``reflection'' of a type, variable, or namespace. This reflection is a value of type \texttt{std::meta::info}.

\begin{lstlisting}[language=C++]
#include <meta>
#include <iostream>

struct MyStruct {
    int x;
    double y;
};

constexpr auto info = ^MyStruct;
\end{lstlisting}

\subsection{\texttt{template for} and Splicing}
C++26 introduces \texttt{template for} to iterate over reflections at compile time, and splicing (\texttt{[: :]}) to turn a reflection back into a language entity.

\begin{lstlisting}[language=C++]
template<typename T>
void print_members(const T& obj) {
    constexpr auto members = std::meta::members_of(^T);
    
    template for (constexpr auto m : members) {
        if constexpr (std::meta::is_data_member(m)) {
            std::cout << std::meta::name_of(m) << ": " << obj.[:m:] << "\n";
        }
    }
}
\end{lstlisting}

\section{Contracts}

Contracts provide a formal way to specify preconditions, postconditions, and assertions. Unlike \texttt{assert()}, contracts are part of the function's interface and can be used by the compiler for optimization or by static analysis tools.

\subsection{Syntax}
\begin{lstlisting}[language=C++]
int divide(int a, int b)
  pre { b != 0 }             // Precondition
  post(r) { r * b == a }     // Postcondition (r is the return value)
{
    return a / b;
}
\end{lstlisting}

\subsection{Violation Handlers}
C++26 allows you to define what happens when a contract is violated:
\begin{itemize}
    \item \textbf{\texttt{enforce}}: Terminate the program.
    \item \textbf{\texttt{observe}}: Log the failure and continue (Undefined Behavior if the condition was critical).
    \item \textbf{\texttt{ignore}}: The compiler assumes the contract is true for optimization.
\end{itemize}

\section{Pack Indexing}

Accessing elements in a variadic pack used to require complex recursive templates or \texttt{std::get} with \texttt{std::tuple}. C++26 adds direct indexing.

\begin{lstlisting}[language=C++]
template<typename... T>
void get_first(T... args) {
    auto first = args...[0]; // Direct access to the first element
    using FirstType = T...[0]; // Direct access to the first type
}
\end{lstlisting}

\section{Structured Bindings Improvements}

\subsection{The \texttt{\_} Placeholder}
You can now use \texttt{\_} to indicate that a binding is intentionally unused, silencing compiler warnings.

\begin{lstlisting}[language=C++]
auto [id, _, score] = get_student_data();
std::cout << "ID: " << id << ", Score: " << score << "\n";
\end{lstlisting}

\subsection{Attributes on Bindings}
You can now apply attributes like \texttt{[[maybe\_unused]]} to individual bindings.

\begin{lstlisting}[language=C++]
auto [[maybe_unused]] [x, y] = point;
\end{lstlisting}

\section{Erroneous Behavior}

This is a major safety milestone. C++26 defines ``Erroneous Behavior'' for cases like reading uninitialized memory. Instead of being ``Undefined Behavior'' (where anything can happen), it is now ``Erroneous''. The compiler is encouraged to initialize memory to a specific ``dead'' value and the behavior is predictable.

\section{Senders and Receivers (\texttt{std::execution})}

The long-awaited async model. It provides a standard way to compose asynchronous tasks across different execution resources (threads, GPUs, thread pools).

\begin{lstlisting}[language=C++]
auto pipe = schedule(my_pool)
          | then([] { return 42; })
          | then([](int x) { return x * 2; });

auto [val] = std::this_thread::sync_wait(std::move(pipe)).value();
\end{lstlisting}

\section{Linear Algebra (\texttt{std::linalg})}

Standardized BLAS support. This allows C++ to compete with Fortran and Python (NumPy) natively.

\begin{lstlisting}[language=C++]
#include <linalg>

std::vector<double> v1 = {1, 2, 3}, v2 = {4, 5, 6};
auto result = std::linalg::dot_product(v1, v2);
\end{lstlisting}

\section{Godhood Summary: Why C++26 Matters}
C++26 closes the ``Safety'' and ``Reflection'' gaps that have plagued the language. With \textbf{Contracts}, \textbf{Erroneous Behavior}, and \textbf{Reflection}, C++ remains the fastest language while becoming significantly safer and more expressive than its predecessors.
