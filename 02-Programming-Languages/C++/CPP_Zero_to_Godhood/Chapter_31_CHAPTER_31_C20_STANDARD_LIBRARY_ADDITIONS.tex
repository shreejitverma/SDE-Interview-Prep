\hypertarget{stdformat-python-style-formatting}{%
\subsection{\texorpdfstring{1. \texttt{std::format} (Python-style
Formatting)}{1. std::format (Python-style Formatting)}}\label{stdformat-python-style-formatting}}

Type-safe, fast, and readable string formatting. Replaces
\passthrough{\lstinline!printf!} and \passthrough{\lstinline!iostream!}.

\begin{lstlisting}[language={C++}]
#include <format>
#include <iostream>

std::string s = std::format("Hello, {}! The answer is {}.", "World", 42);
// "Hello, World! The answer is 42."

// Positional arguments
std::string s2 = std::format("{1} {0}", "World", "Hello");
\end{lstlisting}

\hypertarget{stdspan}{%
\subsection{\texorpdfstring{2.
\texttt{std::span}}{2. std::span}}\label{stdspan}}

A non-owning view of a contiguous sequence (array, vector). Replaces
\passthrough{\lstinline!pointer + size!}.

\begin{lstlisting}[language={C++}]
#include <span>

void process(std::span<int> data) {
    for (int& x : data) x *= 2;
}

int arr[] = {1, 2, 3};
std::vector<int> vec = {4, 5, 6};

process(arr); // Works
process(vec); // Works
\end{lstlisting}

\hypertarget{stdjthread-joinable-thread}{%
\subsection{\texorpdfstring{3. \texttt{std::jthread} (Joinable
Thread)}{3. std::jthread (Joinable Thread)}}\label{stdjthread-joinable-thread}}

Automatically joins on destruction. Supports cooperative interruption
(\passthrough{\lstinline!stop\_token!}).

\begin{lstlisting}[language={C++}]
#include <thread>

void worker(std::stop_token st) {
    while (!st.stop_requested()) {
        // work...
    }
}

{
    std::jthread t(worker);
} // t requests stop and joins automatically here
\end{lstlisting}

\hypertarget{modules-the-semantic-revolution}{%
\subsubsection{7.1 Modules: The Semantic
Revolution}\label{modules-the-semantic-revolution}}

Modules replace textual inclusion with a binary semantic model,
fundamentally changing the Compilation Pipeline.

\begin{itemize}
\tightlist
\item
  \textbf{Physical Structure \& BMI}: A Module Interface Unit
  (\passthrough{\lstinline!.cppm!}/\passthrough{\lstinline!.ixx!}) is
  compiled into a \textbf{Binary Module Interface (BMI)}. Unlike
  headers, which are re-parsed in every translation unit, the BMI
  contains a serialized AST (Abstract Syntax Tree). Importing a BMI is a
  constant-time operation rather than a linear-time parsing task.
\item
  \textbf{Build System Integration}: Modules introduce a strict
  compilation order. If \passthrough{\lstinline!main.cpp!} imports
  \passthrough{\lstinline!math!}, the BMI for
  \passthrough{\lstinline!math!} must exist first. Modern build systems
  (CMake 3.28+, Ninja) now include a ``scanning'' phase to dynamically
  generate the dependency DAG before compilation begins.
\end{itemize}

\hypertarget{compilation-pipeline-with-modules}{%
\paragraph{Compilation Pipeline with
Modules}\label{compilation-pipeline-with-modules}}

\begin{lstlisting}
graph TD
    A[Module Interface: math.cppm] -->|Compiler| B(BMI: math.pcm)
    A -->|Compiler| C(Object File: math.o)
    D[Source: main.cpp] -->|Scan Dependencies| E{Build System}
    E -->|Wait for BMI| B
    B -->|Import| D
    D -->|Compile| F(Object File: main.o)
    C -->|Linker| G[Executable]
    F -->|Linker| G
\end{lstlisting}

\hypertarget{coroutines-stackless-state-machines}{%
\subsubsection{7.2 Coroutines: Stackless State
Machines}\label{coroutines-stackless-state-machines}}

C++ coroutines are stackless, meaning they don't have a private call
stack. Their state is stored in a heap-allocated \textbf{Coroutine
Frame}.

\begin{itemize}
\tightlist
\item
  \textbf{Lifecycle of \passthrough{\lstinline!promise\_type!}}:

  \begin{enumerate}
  \def\labelenumi{\arabic{enumi}.}
  \tightlist
  \item
    \textbf{Allocation}: Frame is allocated on the heap.
  \item
    \textbf{Initial Suspend}:
    \passthrough{\lstinline!co\_await promise.initial\_suspend()!}
    determines if the coroutine starts immediately or waits.
  \item
    \textbf{Body}: Executes until a suspension point.
  \item
    \textbf{Final Suspend}:
    \passthrough{\lstinline!promise.final\_suspend()!} allows the frame
    to persist so the caller can retrieve values before destruction.
  \end{enumerate}
\item
  \textbf{The \passthrough{\lstinline!co\_await!} Sequence}: When
  \passthrough{\lstinline!co\_await!} is hit:

  \begin{enumerate}
  \def\labelenumi{\arabic{enumi}.}
  \tightlist
  \item
    \passthrough{\lstinline!await\_ready()!} is checked.
  \item
    If false, \passthrough{\lstinline!await\_suspend(handle)!} saves the
    CPU registers and instruction pointer to the frame and returns
    control to the caller.
  \item
    On \passthrough{\lstinline!handle.resume()!}, the state is restored,
    and execution continues.
  \end{enumerate}
\end{itemize}

\hypertarget{coroutine-state-machine}{%
\paragraph{Coroutine State Machine}\label{coroutine-state-machine}}

\begin{lstlisting}
stateDiagram-v2
    [*] --> InitialSuspend: Call
    InitialSuspend --> Body: Resume
    state Body {
        Execution --> CoAwait: co_await
        CoAwait --> Suspend: Save State
        Suspend --> [*]: Return to Caller\n(Yield Control)
        [*] --> Resumption: Resume()
        Resumption --> Execution
    }
    Body --> FinalSuspend: co_return
    FinalSuspend --> [*]
\end{lstlisting}

\hypertarget{ranges-views-lazy-composition}{%
\subsubsection{7.3 Ranges \& Views: Lazy
Composition}\label{ranges-views-lazy-composition}}

\begin{itemize}
\tightlist
\item
  \textbf{Range vs.~View}: A Range owns or provides access to data; a
  \textbf{View} is a lightweight, lazy range that doesn't own data.
\item
  \textbf{Performance}: Views use expression templates to collapse
  multiple operations (filter, transform) into a single loop. This
  avoids intermediate allocations but can lead to ``Template Bloat'' and
  increased compile times in extremely deep pipe chains.
\end{itemize}

C++20 was the \textbf{Gigantic Leap}. It is as significant as C++11 was
a decade prior, introducing four ``Great Pillars'' that redefine how we
write C++. 1. \textbf{Concepts}: Type-safe templates with readable
errors. 2. \textbf{Modules}: The end of the ``Header/Source'' and
\passthrough{\lstinline!\#include!} era. 3. \textbf{Coroutines}: Native
support for asynchronous programming and generators. 4. \textbf{Ranges}:
Composable, functional-style container operations.

\textbf{The Golden Rule of C++20}: Constraints over SFINAE, Modules over
Headers, and Ranges over Iterators. You have leaped into a new era of
C++ architecture.
